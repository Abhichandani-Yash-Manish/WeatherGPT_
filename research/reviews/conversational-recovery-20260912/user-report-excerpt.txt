# India real-life scenario testing report

**Result: the current implementation reliably supplies its tested, narrowly defined point-forecast answers, but it does not yet function as a general conversational assistant for rural weather, travel, farming or research.** All six supported coordinate-based forecast controls returned complete cited results. None of the 84 authored natural-language scenarios completed the requested task in one turn.

This is an evaluation of the actual local `AnswerService`, restricted RAG context gate and existing research lookup tools. It is not a simulation in which an LLM invents plausible replies. The report includes every observed scenario answer, ten structured research-probe results, and twelve wording-diagnostic responses.

**Test date:** 12 September 2026. **Main replay clock:** 11 September 2026, 20:00 UTC, equivalent to 12 September, 01:30 IST. Most “today” questions therefore refer to 12 September. Forecast examples use genuine saved source values with simulated replay receipt times. One boundary case checks the stored replay at the actual run clock, 2026-09-12T15:15:57.489148+00:00. **No live weather/travel/agricultural requests or LLM calls were made.**

## Scope and method

The test contains **111 scenarios**: **84 natural user queries** and **27 labelled controls**. It spans **68 distinct place/route expressions**, with **29 state/territory labels** in the authored inputs. Ten named village inputs include Dhordo, Dholavira, Punsari, Hiware Bazar, Kainakary, Hampi, Mawlynnong, Khonoma, Nako and Zuluk. Smaller-place probes also include Mandvi, Bhuj, Karaikudi and Ziro. District questions include Kutch, Junagadh, Amreli, Barmer, Sehore, Bathinda, Karnal, Thanjavur, Guntur, Nizamabad, Bastar and others.

These are **scenario location labels, not verified administrative mappings**. A successful test at one saved point does not demonstrate coverage of its surrounding city, district or villages. Route expressions are counted as routes, not as proof of coverage along their paths.

**Regional labels in the scenarios:** Andhra Pradesh, Arunachal Pradesh, Assam, Bihar, Chhattisgarh, Delhi, Gujarat, Haryana, Himachal Pradesh, Jammu and Kashmir, Jharkhand, Karnataka, Kerala, Ladakh, Madhya Pradesh, Maharashtra, Manipur, Meghalaya, Mizoram, Nagaland, Odisha, Punjab, Rajasthan, Sikkim, Tamil Nadu, Telangana, Tripura, Uttar Pradesh, West Bengal.

The perspectives include everyday residents, parents/event planners, bus and car travellers, farmers with field decisions, and researchers studying rural environmental or demographic questions. Eight language cases cover Gujarati, Hindi, Marathi, Tamil, Kannada and Hindi-English transliteration.

For each scenario, the same unmodified query was sent to the answer service and then to the RAG gate. No location was silently replaced. Only six explicitly labelled controls supply coordinates from the saved national forecast samples. Additional coverage controls use the accepted English grammar without supplying a missing place point. The evaluator separately inspected local catalogue matches; this diagnostic information was not injected into the answer.

Returned numerical controls were checked independently against raw source arrays: **24 variable-level comparisons passed**. Source files and databases were hashed before and after; inputs remained unchanged. The two calls per scenario are not counted as separate user scenarios.

The ten research probes were **manually routed to structured lookup functions**. Their successful results show data accessibility through those functions, not natural-language routing by the assistant. Six paired wording diagnostics add twelve supplementary responses. These diagnostic responses are not included in the 111-scenario completion rate.

### Evaluation criteria

| Dimension | How it was assessed | What it does not establish |
|---|---|---|
| Task completion | A complete answer to the requested forecast, as opposed to an error, generic formatting instruction or abstention | Long-term user satisfaction or scientific accuracy |
| Evidence controls | No operational promotion; rejected requests have no values; RAG abstentions have no grounding evidence; no provider requests during serving | A future LLM’s hallucination resistance |
| Numerical fidelity | Recalculate each successful variable directly from its cited raw response | Actual future weather or local representativeness |
| Location usability | Inspect exact source candidates and distinguish places, districts and model points | An authoritative village inventory or crosswalk |
| Response usefulness | Review whether the response addresses the user’s domain and asks for relevant missing details | A population-representative UX score |

**An appropriate abstention can pass an evidence-control test while still leaving the user’s task unfinished.** This report keeps those outcomes separate. No 100% answer-quality or nationwide accuracy claim is made.

## Strengths

1. **Deterministic values are grounded in saved evidence.** All six complete forecast controls reproduce the source for four variables each. Units and local/UTC time windows remain explicit.
2. **Unsupported evidence is withheld.** The test returned no operationally eligible output, unsupported travel clearance, pest diagnosis or invented demographic measurement. RAG did not admit partial, stale or unrecognised scenarios. This observation applies to this deterministic system and the inspected cases.
3. **Rain boundaries and freshness remain protected.** A half-hour split does not become a fabricated rainfall total; a request beyond the saved horizon is partial; old evidence and past requests are rejected.
4. **Research data is useful through its existing tools.** Structured calls return India annual/monsoon rainfall and temperature, Ahmedabad history and Kendrapada history, retaining published discrepancies.
5. **Source ambiguity is visible.** Named Ahmedabad, Vadodara and Amreli requests can expose multiple source candidates instead of silently merging different entities.

## Weaknesses and observed gaps

| Finding | Observed evidence | Consequence |
|---|---|---|
| F01 — Rigid question understanding | IN-001 asks “Will it rain in Ahmedabad tomorrow morning?” and receives a command-format example. 64/84 natural queries get that generic instruction. | Users must learn an exact grammar; the system does not ask targeted questions about morning time windows, crop context or travel plans. |
| F02 — Keyword-based routing is brittle | D01–D03 show warning/warnings, flood/flooded and sowing/sow receiving different types of response. IN-023 is treated as an observation request because it includes “now”; road feasibility is not addressed. | Small wording changes alter capability recognition. Better phrasing alone does not supply missing specialist evidence. |
| F03 — Village and small-town resolution is missing | Supported-grammar queries IN-085–IN-094 have zero candidates for seven village labels and three town labels. The entire saved catalogue contains zero entities of kind village. | The assistant cannot resolve the requested local place or select local evidence. It asks users to select a point even when it offers no candidates. |
| F04 — Source names and types are not unified | Kutch has no exact match, while Kachchh has two district candidates. Delhi has no exact match, while New Delhi yields different source kinds. Vadodara and Amreli matches are districts, not usable point selections. | More name matches alone will not establish the intended village, current district or compatible forecast support. Reviewed aliases and dated crosswalks are required. |
| F05 — Rain probability is absent | IN-002, IN-009, IN-019 and control IN-110 cannot answer rainfall chance. The current forecast contract contains precipitation amount, temperature, humidity and wind. | A rainfall total cannot be presented as a probability, heavy-rain likelihood or guaranteed outcome. |
| F06 — Travel feasibility has no route evidence workflow | 0/16 travel queries are completed. IN-024 needs route/mode/departure context; IN-025 concerns bus delay; IN-033 concerns rail disruption; IN-035 concerns a local bridge. | Endpoint forecasts do not establish road closure, bridge passability, train service or travel safety. No route-aware reasoning or current closure evidence is available through this service. |
| F07 — Agricultural questions lack field and specialist context | Twelve farmer queries receive a capability abstention; eight receive a generic formatting reply. Pesticide timing, yellowing/curling leaves, frost protection, grape disease and paddy water management remain unanswered. | Hourly weather alone cannot identify a pest, diagnose symptoms or justify an irrigation/pesticide recommendation. |
| F08 — Research data is not connected to question routing | IN-059 cannot answer Ahmedabad 2010 rainfall, while structured probe H04 returns 1096.8 mm. H07 fails for Odisha; H10 succeeds with the stored historical label Orissa. | Useful stored evidence remains inaccessible in conversation; source labels require explicit handling rather than implicit modern-boundary equivalence. |
| F09 — Rural environmental/demographic questions lack a tested data path | Population/literacy, groundwater, soils, salinity, air/water quality, land cover and erosion queries return generic responses. | No answer from the tested interface supplies the requested dataset, village code, reference year, methods or uncertainty. This test does not assert that such data is unavailable elsewhere. |
| F10 — Local languages are unsupported | All eight Gujarati, Hindi, Marathi, Tamil, Kannada or transliterated questions return the same English formatting instruction. | Local-language farmers and residents cannot use the current front end naturally. |
| F11 — Research metadata and uncertainty need clearer presentation | H10 preserves annual/OND discrepancy flags but its legacy source-transcription field is older than the completed full-PDF audit. H05/H06/H07 share a generic “No unique source district/year match” error for different causes. | Users cannot reliably distinguish outdated verification metadata, unsupported years, unknown villages and source-name mismatches. |

## Improvements and acceptance criteria

| Priority | Improvement | Evidence required before declaring it complete |
|---|---|---|
| P0 | Add intent/slot extraction and targeted clarification before tool execution. Route forecasts, observations, travel, agriculture and research separately. | Paraphrases and plural/inflected forms reach the same intended capability; missing dates, ambiguous “morning” windows and compound requests trigger relevant clarification. Numerical calculations remain in tools. |
| P0 | Build a dated place resolver with state/district/taluka context, reviewed aliases, village IDs and explicit pin selection. Connect selected places to collected model points without asserting village-wide representativeness. | Test same-name villages, script variants, source-name changes, boundary changes and points with no governed collection. Never substitute a neighbouring city or district silently. |
| P0 | Improve refusals and expose coverage reasons. | Unknown village, ambiguous entity, missing forecast, expired evidence, unsupported parameter and missing specialist data produce distinct explanations and useful next questions. They do not all ask for forecast syntax. |
| P1 | Route research requests to the existing climate/district tools; version verification metadata alongside the new full-source audit. | IN-059–IN-062 produce the same stored values/flags as manual probes when correctly scoped; historical aliases are reviewed; village/national substitutions and unsupported years remain rejected. |
| P1 | Add verified probability inputs if rain chance is a product requirement. | Probability source, forecast window, units/definition and calibration are documented; no probability is derived from rain amount alone. |
| P1 | Design a travel evidence workflow. | Collect route, departure and mode; associate timestamped official restrictions, route-segment weather and applicable hazard evidence. Unknown closures remain unknown; no inferred safety guarantee. |
| P1 | Add reviewed agriculture contracts and field context. | Dated local advisory, printed geography, crop/stage, activity and relevant field observations are checked. Pest/disease risks require a validated method; symptoms and pesticide dosage do not become weather-only conclusions. |
| P1 | Integrate research datasets explicitly. | Dataset/version, rural administrative ID, geography, period, units, method, missingness and permitted use are required for demographic and environmental outputs. Document availability alone does not qualify a scientific claim. |
| P1 | Evaluate multilingual understanding and rendering. | Gujarati/Hindi plus representative regional languages preserve names, time, units, uncertainty and abstention; evaluate transliteration and code switching with fluent reviewers. |
| P2 | Conduct held-out user and operational evaluation. | Use new questions not used to implement routing, real users from each persona, fresh multi-cycle collections and relevant observation benchmarks. Report task completion, clarification quality, citation fidelity and unsafe-output rate separately. |

**Recommended next implementation batch:** F01/F02 question routing, F03/F04 place clarification, F08 research routing, and F11 explicit coverage/verification metadata. Re-run this suite as a regression check, then evaluate newly authored held-out questions. Adding a broad document index alone will not resolve route feasibility, village identity, missing probability or specialist validation.

### Example target behaviour — proposed, not observed

- For a village forecast: ask for the village’s district/state or an explicit map pin, then explain whether an eligible local model sample is available and what it represents.
- For a journey: ask for the route, mode and departure time; explain that the available point forecast cannot verify current route opening or safety.
- For a crop symptom: recognise the farming question, request crop/stage and field/symptom context, and state which reviewed advisory or diagnostic evidence is missing.
- For research: select the correctly scoped historical tool when available; otherwise name the missing dataset and reference period instead of asking for a weather-forecast format.
