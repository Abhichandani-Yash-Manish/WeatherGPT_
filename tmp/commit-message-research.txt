Research the frontend landscape and decide the stack before the React overhaul

The user asked for deep research across component libraries and references first, and for the product philosophy
to move to chat-first: the conversation is the product, every other surface becomes an additive, reusable module.

Decided in docs/87: Vite + React + TypeScript to web/dist; Tailwind v4 CSS-first theme seeded from tokens.css;
shadcn/Radix primitives with React Aria/S2 where Radix has no equivalent; assistant-ui as the transcript library
(distributed through the shadcn registry, so its source lands in the repo, no runtime CSS-in-JS, RTL through
logical classes) mapped onto our engine packet rather than its runtime; TanStack Query/Table/Virtual for state,
long threads and 72-row answers; viz.js kept as the measurement engine for evidence charts with shadcn/Tremor
allowed only for KPI blocks if measured in; Motion with reduced-motion gating; Lucide icons; self-hosted
per-script Noto woff2 subsets; Vitest + Testing Library + MSW + axe-core for the ported 110 checks; the existing
headless-Chrome runner kept as the browser acceptance harness.

The chat-first architecture is recorded too: one module registry derived from the backend capability catalogue,
each module exposing a compact Block, a full Surface and its intents, so a capability is reachable through the
conversation and escalatable to a workbench panel while deep links keep working.

One policy cost is stated rather than taken silently: style-src self blocks inline style attributes, which
positioning, virtualisation and animation libraries require, so docs/87 recommends style-src-attr unsafe-inline
with script-src left strict, and six decisions are put to the user before R0 starts. Nothing is installed yet.
